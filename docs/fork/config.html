Configure herdr+

What you can turn on or off in herdr+, what it starts as, and where to change it.

Config file

~/.config/herdr/config.toml ($XDG_CONFIG_HOME/herdr/config.toml when that is set; debug builds use herdr-dev). herdr --default-config prints a commented default file; the full key reference is docs/next/website/src/data/config-reference.json.

⚙

Settings panel · prefix+s

ctrl+b, then s. Sections: theme, indicators, sound, toasts, integrations, backups, reminders, closed, news, browser, coordinator, agents. Settings rows write the same config.toml keys; the browser, coordinator and agents sections ask the server to write its own config and reload it.

Docking: macOS, the herdr on this machine, herdr directly in a terminal window (Ghostty measured exactly; other terminals best effort). Clicking the page gives it the keyboard; clicking the terminal, or cmd+esc in the browser, gives it back. While the browser is not over its area the area says why (starting, not running with a Start button, not installed, stopped after crashes with a Restart button, "click here once" when several terminal windows could be this one, or why it cannot dock). Tabs with pages wear a dim ◎; the companion's count pill (3 · 12) lists every session with pages.

Companion browser: the Electron app in apps/companion; apps/companion/scripts/try.sh tries it against a throwaway herdr in one command (run it in a plain terminal).

Legacy keys: wrap_agents is only read as a fallback for [agents] wrap (a Settings change to wrap removes it), and shell_hook is inert. The commented default file still says stop_with_server is not honoured; it is.

08 · updates · upstream

Updates [update]

FeatureDefaultWhere to changeIn Settings?

Version check

offupstream's default is on
[update] version_check = true
config only

Agent detection manifest check

offupstream's default is on
[update] manifest_check = true
config only

!Both are off on a herdr+ build, and should stay off.

version_check polls herdr.dev/latest.json in the background, so upstream releases show up as "update available" on a fork binary; the check itself only notifies. Do not follow that prompt: herdr update ignores version_check, fetches the same upstream manifest, and when upstream's version is newer than the fork's it downloads the upstream binary, verifies its checksum and renames it over the herdr+ binary on disk (current_exe). It refuses inside herdr and on Homebrew, mise or Nix installs. Before installing it asks to stop or live-hand-off running servers, and a handoff relaunches them on the upstream binary. After that you run upstream herdr, not herdr+.

manifest_check downloads herdr.dev/agent-detection/index.toml. A remote manifest at the bundled version or newer replaces the fork's bundled detection rules; only the fork's signal rules survive.

cmd+[ / cmd+] only work if your terminal passes Cmd through to herdr; most macOS terminals keep Cmd for themselves. That is why alt+, / alt+. are bound too: they reach herdr in any terminal that sends Option as Alt (Ghostty: macos-option-as-alt = true; iTerm2 and Terminal.app have the same setting). herdr takes them before the pane, so your shell no longer sees alt+. (insert last argument). The toolbar's ‹ › buttons always work. Ghostty passes Cmd on with keybind = super+[=csi:91;9u and keybind = super+]=csi:93;9u.

Suggested key set

Everything else above stays unbound until you bind it. This is one full set, all on direct keys; copy what you like into [keys]:

previous_tab, next_tab, new_tab, rename_tab, switch_tab and open_notification_target replace their prefix+... defaults; add those back in a list to keep both, e.g. next_tab = ["alt+d", "prefix+n"]. tab_history_back here drops the default alt+,; tab_history_forward keeps its defaults. Alt-letter keys only reach herdr when the terminal sends Option as Alt, and herdr takes them before the pane, so they shadow your shell's word keys (alt+d deletes a word, alt+t swaps words, alt+c capitalizes one). Change any of them to keys you do not use there.
