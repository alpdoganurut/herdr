01 · coordinator

A coordinator agent, run by herdr itself

One long-running Claude Code session that knows who is doing what, keeps a dashboard, remembers what you tell it, and acts when you ask. It doesn't relay messages: agents talk to each other directly, and it reads the log.

◉Native, server-run

You never run it yourself: herdr starts it in its own coordinator tab, resumes it after restarts and relaunches it if it disappears. Turn it on with [coordinator] enabled = true.

▤HTML dashboard on 127.0.0.1:7718

One page with every agent's status, recent messages and actions, plus the coordinator's own summaries and suggestions. Opens in herdr's browser or yours.

❖Its own memory

It remembers what you tell it across restarts: one fact per file, with an index it reads every time it starts or wakes.

⊘Acts only on your word

It changes things only when you asked, by typing in its pane. When it wakes up by itself, it updates the dashboard and makes suggestions, but changes nothing.

02 · agents control herdr

Agents can drive herdr, within clear rules

Every Claude Code or Codex agent can get the herdr_agents tools to read, message and manage other tabs. herdr checks every request against the rules below and logs every change and every refusal.

›Your turns are tracked

herdr knows whether an agent's turn started from your typing or from a message, a script or a wake-up. Risky actions need a turn you started.

≡Actions log

Every agent change, every refusal, and your own tab and team actions are logged. You see them on the dashboard; agents read them with agents_actions.

≤Loose limits

Generous limits stop a runaway agent: 200 messages an hour, 30 between the same two agents in 10 minutes, 20 new tabs an hour, 300 other tab changes (renames, moves, roles, mutes) an hour.

03 · teams

Turn a group into a team

A group of tabs becomes a team with a purpose and roles. Members know each other from their first turn.

◆Make team from a group

Use Make team… on the group menu, herdr team make <group> --purpose "<text>", or ask the coordinator. The group header then shows ◆ <purpose>.

@Roles name the members

Every Claude Code or Codex agent started in the group joins, named after its role: fixer, reviewer, reviewer-2. Agents message a member by its role.

≣Members know the team

Every member knows the roster, roles and purpose from its first turn, and hears about changes on its next step.

↩Report-back rule

A member that finishes, gets stuck on, or drops work it was given sends whoever gave it the work one short report: what is done, where the details are, what is next.

04 · agent-to-agent messaging

Messages that never type over you

Agents can message each other without ever typing over your half-written prompt: herdr queues each message and types it in when the agent is free and you aren't typing.

what the receiving agent sees
> herdr+ message m_7f3a from reviewer (teammate, w3:p2): read it with agents_messages id=m_7f3a ● agents_messages(id="m_7f3a") ⎿ from reviewer · "auth review done, 2 issues in session.rs, details in review.md"

⇶A queue per agent

Each agent gets its own queue, oldest first, kept across restarts. Messages expire after 2 h (24 h if the agent is waiting for you) or when the agent's tab is gone.

‖Typing guard

Nothing is typed while you have typed in that pane in the last 10 s or left an unsent draft. If Claude Code or Codex shows no input box (a question, a permission prompt, a menu), the message waits.

❝One short line, not a paste

The agent gets one short line naming the sender and a message id, then reads the full message itself, so Claude never mistakes it for something you pasted.

⧉Together, once, on time

Waiting messages go in together, as one line, once the agent has been idle for 3 s. One the agent picks up while waiting is never also typed in or handed out twice, and a wait ends at 100 s with a normal result, before Claude Code's 120 s tool limit.

⏱Stuck-message notice

If a message has waited 10 min on an agent whose screen hasn't moved, the sender gets one notice saying why, for example that the agent is still running a subagent.

↵Enter only when it landed

herdr presses Enter only once the text shows in the agent's input box and you haven't typed since; otherwise the sender is told why. herdr never resends a message on its own.

?Waiting on you

When an agent is waiting for your answer, messages to it wait too. After 10 min the senders are told, and you get one card. Held messages last up to 24 h; senders hear when one expires.

!Urgent interrupt, safely

urgent=true presses Esc once on a working agent and puts the message first. Only when you asked for it or from the coordinator, at most once every 5 min between the same two agents, and never into a dialog, voice mode or while you type.

↯No false "busy"

Claude Code tells herdr when each turn starts and ends, so messages aren't held back by background agents that keep its spinner going.

⇣Backlog first

An agent waiting with agents_wait_for_message gets the messages already queued for it first; agents_messages inbox=true lists them without taking them.

✉Quiet messages

For an FYI that shouldn't interrupt: quiet=true holds the message, and the Claude agent sees it, with sender and time, at its next prompt. Nothing is lost if delivery fails. The tab row shows ✉3.

☾Do not disturb

Keeps an agent focused: every message to it becomes a quiet one, urgent ones are refused, and herdr types nothing in. Your own typing is unaffected; the coordinator gets through only if an agent turned it on, not you. Tab menu, herdr tab dnd on, or a teammate's agents_dnd; shows a ☾ in the row.

❯Suggestions are not approvals

When an agent reads another agent's screen, herdr marks the prompt box as either a dim suggestion from the agent or an unsent draft you typed, so a suggestion is never taken as your answer.

send→queued (busy / typing / blocked)→idle 3 s + guard clear→short line typed→read by id

05 · sidebar

A sidebar that shows who needs you

One row per tab across every workspace, grouped and foldable, with blocks for what's active, pinned and scheduled, so you see at a glance who needs you.

●Session header

One row on top of the session area: the tab's status as an icon (● working, ○ idle, ◉ blocked, ◌ suspended, ↻ restarting), its name, the context use from 75% and ⚭ subagents / ✉ waiting messages when there are any. On the right the Terminal / Browser view tabs with the browser dock toggle ◧, and the notes toggle ▤ at the far edge. The active view and the open dock are accent, the rest dim: colour only, no boxes.

On a narrow window the name gives way first, then the view tabs shrink to T B; the dock toggles always stay.

◧One dock slot

The right edge holds one dock: your notes or the browser, never both. ▤ and ◧ swap it and each keeps its own width; drag the divider to resize. Each dock has a title bar: ▤ Notes ✎ ✕ and ◧ <page title> ⤢ ✕, where ⤢ turns the tab to Browser view. In Browser view the notes stay beside the page.

▾Active · Pinned · Scheduled

Active: every busy tab, the ones that need you first. Pinned: tabs you pin from the menu. Scheduled: tabs with a reminder and the time to the next one. Folded blocks still show their count.

◌Suspended runs fold

Three or more suspended tabs in a row become one ◌ N suspended ▸ row. Hover lists them. Off in Settings → Indicators (fold suspended runs).

%Context use

Shows when an agent is running out of room: a percentage on the row and in the session header from 75% (yellow, red from 90%). Read from the agent's own session file, never on every frame.

▦Context menus with sections

Every right-click menu has the same layout: titled sections, one icon per item, your own key bindings shown on the right, and destructive items in red at the bottom.

⏶The toolbar

The top row of the sidebar keeps the everyday moves one click away. At rest it shows only the buttons; hover it and the search field and recency chip appear (they stay while a filter is on).

✎Your page, edited in place

One markdown page per agent session, for a plan, a checklist or anything else. Click to edit; it saves on Esc or after 2 s. - [ ] tasks tick with a click. Open it with the session header's ▤ or the tab menu; key bindings are on the configuration page.

❦Markdown, drawn for a terminal

Headings, bold, italic, links, lists, quotes, code blocks and tables, drawn for the terminal. Clicking a word edits it in place.

◇Agents write it when you ask

Ask the agent, or run /plus:notes for a short page with what's in flight, what's waiting on you and the plan (it opens the pane too). Once asked, the agent keeps it up to date. It is one page, not a running log. An agent never swaps out a browser you docked: while it is docked the notes stay closed.

↻Survives /clear and compaction

The page (its first 3 KB) goes back into the agent's context on start, resume, /clear and compaction, so the agent never loses the plan.

▣Agent cards (agents_notify)

An agent can pin a card for you: info, question, done or warning, coloured from your theme, with its team and role on the border. Questions ring; done plays the done sound.

✍You decide when

Tell an agent when to ping you and about what, with /plus:notify or in your own words. It saves that in a ## Notify section of its notes and follows it.

◆Toasts name the team

herdr's own pop-ups (finished, needs attention, reminders) name the team and role, for example api rewrite · builder, and move left of the notes pane when it's open.

∅Per-tab mute

Silences a tab's pop-ups, sounds, bells and reminders; cards from its agent still show. Tab menu, herdr tab mute, or a teammate's agents_mute.

★Reminders and important tabs

Important: herdr keeps reminding you while the agent is waiting for you. Remind: a nudge every 5m, 10m, 30m, 1h, 6h or daily, whatever the agent is doing, optionally as a card.

08 · more

Smaller things that add up

◫Agent wrap & Settings → Agents

herdr agent wrap claude|codex gives your agents the herdr_agents tools and herdr+ instructions. It's off by default: Settings → Agents turns it on and shows the .zshrc line before changing anything. The same page sets auto handoff, autosuspend and Claude's status reports.

⏎Launches never get cut off

herdr waits until a new tab's shell is ready before starting the agent, and runs long commands from a script so nothing is cut off.

◈Better detection

Codex voice mode shows on the tab. A Claude whose turn ended while background agents run reads idle, not working.

⌁Claude's own status

Claude Code reports its own status to herdr: working, blocked on a question, done, and each background subagent. Screen detection still decides; herdr agent explain shows both side by side. Turn it off with [agents] program_status = false.

⎘Copy session ID

Tab and pane menus copy the Claude Code session ID or Codex thread ID, for --resume elsewhere.

⇆cmd+[ / cmd+] tab history

Back and forward through the tabs you focused, like a browser. Closed tabs are skipped. alt+, / alt+. work too, and so do the ‹ › buttons at the start of the tabs toolbar.

⤧Drag & drop and resize fixes

Drops land where the marker shows. Resizing the window is smoother and the sidebar no longer flickers.

◎Built-in browser

herdr runs a browser for agents (herdr-browser MCP): the herdr+ companion, one group of pages per herdr tab that follows the tab you focus, a glow and cursor while an agent acts, password fields protected, never takes your keyboard. herdr browser setup --companion installs it; herdr starts it on an agent's first page, restarts it after a crash and quits it with the server. Dock it beside the terminal with the header's ◧, or switch the tab to Browser view. Start, stop, restart and focus it from Settings → Browser, the Browser overlay or herdr browser companion.

⏸Suspend, activate, restart

Suspend an idle agent to free resources and bring it back later in the same pane and session. If it's still busy (working, a subagent, a background shell, a /loop), suspend is refused and the notice offers Force suspend or Force restart. Only you can force it, not agents. While it restarts or wakes, the pane reads ↻ restarting or ↻ waking; if that gives up, the suspended card says so. If the agent never starts (the shell is back at its prompt), the pane unlocks within a few seconds and a toast says so.

⏲Autosuspend

Suspends a Claude agent you've seen and left idle for a set time ([agents.autosuspend] after = "1d", off by default). It never touches one that needs you, is on screen, is busy in the background or has messages waiting. A message to it wakes it up.

⌂Removed worktree, session back

If a pane's folder was deleted (say, a removed worktree), herdr recreates it empty after a restart so --resume still finds the session. You get one card, and the agent is told so it can warn you.

⇢Backgrounded Claude sessions

When you background a Claude session it continues under a new ID. herdr follows it, so resume, restart and restore pick up the newest session and its tools still work as that pane.

↺Recently closed sessions

Reopen a closed agent tab with its label, colour, group and reminders: herdr tab closed lists them, herdr tab reopen brings one back, or use Settings → Closed sessions.

■Tab colours & groups

Colour tags, foldable groups, drag tabs and groups, move a tab to a group from its menu.

09 · auto handoff & compact

Auto handoff & compact

When a Claude agent's context fills up, herdr has it write a handoff, compacts it, and brings it back on the same work, without you pasting anything.

80% context or manual→transcript snapshot→handoff.md→/compact→resume

◔Two ways to start

Automatically when context reaches [agents.handoff] at_percent (80 by default, 0 turns it off), once each time and only while the agent is idle. Or by hand: the tab menu's “Handoff & compact”, a key, or herdr agent handoff <target>.

⚙Your handoff skill, or herdr's

Set command to your own skill with a {path} placeholder, or leave it empty to use herdr's prompt. If the agent writes nothing, herdr writes a basic handoff from the notes, git state and recent prompts.

⌸Known place, nothing lost

Each run keeps the transcript and the handoff in a folder per session and time, and the newest one is always easy to find. The sidebar shows “handoff 12m ago”.

▶Back to work

After /compact the agent's new context names the handoff and transcript, and a short line asks it to continue, or to pause if nothing was in flight.

⛨Safety net

When Claude compacts on its own or you type /compact, herdr still saves the transcript and a handoff first. Messages wait until it's done. A /clear cancels it.

10 · engineering notes

How the fork stays healthy

⇄Updates without restarts

herdr+ only adds to herdr's protocol, never changes it, so installing an update hands over live: sessions keep running.

§FORK.md merge contract

FORK.md lists everything the fork owns and how to merge upstream; the fork-sync tool reads it and refuses a sync that would collide.

⚖Audited

Big features are reviewed by three independent audits and a second model, then smoke-tested live on a throwaway server.

↑Synced with upstream
