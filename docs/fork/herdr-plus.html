01 · coordinator

A coordinator agent, run by herdr itself

One long-running Claude Code session that knows who is doing what, keeps a dashboard, remembers things for you, and acts for you when you ask. It is not a relay: agents talk to each other directly, it sees the log.

◉Native, server-run

The herdr server starts it in a coordinator tab, resumes it, and relaunches it if it goes missing. Turn on with [coordinator] enabled = true.

▤HTML dashboard on 127.0.0.1:7718

Served by herdr. Live data (agents, status, messages, actions) plus the coordinator's own summaries and suggestions. Opens in herdr's browser or yours.

❖Its own memory

memory/ with one fact per file and a MEMORY.md index it reads on every start and wake-up. State lives in files, so it can restart fresh.

⊘Acts only on your word

Write tools refuse unless the turn started from your own typing in its pane (non_user_turn). Wake-ups update the board and suggest; they never act.

02 · agents control herdr

Agents can drive herdr, within clear rules

Every Claude Code or Codex agent can get the herdr_agents MCP tools. One server-side check decides what each agent may do. Every write and every refusal is logged.

03 · teams

Turn a group into a team

A group of tabs becomes a team with a purpose and roles. Members know each other from their first turn.

◆Make team from a group

Make team… on the group menu, herdr team make <group> --purpose T, or the coordinator. The header shows ◆ <purpose>.

@Roles name the members

Every Claude or Codex started in the group joins. A member is named after its role: fixer, reviewer, reviewer-2. Address one by to="role:lead".

≣Roster in the instructions

The roster, roles and purpose go into the system prompt. Changes reach Claude through a hook on the next prompt, and Codex on its next tool result.

↩Report-back rule

A member that finishes, gets stuck on, or drops work it was given sends one short report: what is done, where the details are, what is next.

04 · agent-to-agent messaging

Messages that never type over you

Sending to a busy agent used to fail or land on top of your half-written prompt. Now the server queues it and types it in at the right moment.

what the receiving agent sees
> herdr+ message m_7f3a from reviewer (teammate, w3:p2): read it with agents_messages id=m_7f3a ● agents_messages(id="m_7f3a") ⎿ from reviewer · "auth review done, 2 issues in session.rs, details in review.md"

⇶Server-side queue

Per target, oldest first. Saved with the session, survives restarts. Expires after 2 h; messages waiting on the target's user are kept up to 24 h. Dropped if the target is gone.

‖Typing guard

Nothing is typed while you typed in that pane in the last 10 s, or have an unsent draft in its input box. For Claude Code and Codex it fails closed: no visible input box (a question, a permission prompt, a menu) means the message waits.

›Pointer-line delivery

One short plain line instead of a paste, so Claude does not treat it as your pasted content. The agent reads the full message by id.

⧉Batch delivery

Several queued messages go in together once the target has been idle for 3 s, as one line.

⏱Stuck-message notice

If a message waited 10 min on an agent whose screen has not moved for 10 min, the sender gets one notice with the reason. A working agent running a subagent says so instead: is running a subagent (12m); it will read your message when that turn ends.

↵Enter only when it landed

Claude Code and Codex get the text first; herdr presses Enter only once their input box shows it and you typed nothing since. Otherwise no Enter, and the sender hears why. Then each message is confirmed (read by id, or a turn started) or reported unconfirmed; never resent on its own.

?Waiting on you

An agent that asks its user something holds its messages (its screen, its own status report, or no input box). After 10 min the senders get a notice (again after 1 h, then every 4 h) and you get one card; held messages live up to 24 h, and every expiry tells the sender.

!Urgent interrupt, safely

urgent=true: one Esc to a working agent, then the message goes first. Only from your turn or the coordinator; once per pair every 5 min. Never into a dialog, voice mode, or while you type.

↯Claude turn hooks

Claude reports each turn's start and end, so messages are not stuck behind background agents that keep its spinner going.

⇣Wait backlog + inbox

agents_wait_for_message returns what is already queued for you first. agents_messages inbox=true lists it without taking it.

✓Exactly once

A waiting agent claims a message before it is returned, so it is never also typed in, and never returned twice.

✉Quiet messages

quiet=true stores an FYI for a Claude agent instead of typing it in: nothing wakes or interrupts it. At its next prompt (or session start) its hook adds them to its context as data, oldest first, with sender and time; past 8 messages the rest wait for the next prompt. The hook acknowledges what it printed, so a timed-out hook loses nothing. Kept 7 days; Claude with integration 15. The tab row shows ✉3; the agent's own status line can read pending/<pane>.json next to herdr's socket.

☾Do not disturb

From the tab menu (or tab.set_dnd): every agent message to that tab becomes a quiet one, the sender is told in DND, queued, urgent ones are refused and herdr's wake-ups wait. You typing is unaffected. A moon in the row's gutter, saved with the session.

◔100 s waits

Waits stop at 100 s, under Claude Code's 120 s mark, and a timeout is a normal result, not a failed tool call.

❯Suggestions are not approvals

agents_read marks a Claude Code or Codex prompt box: a dim suggestion reads (suggestion shown by the agent, not typed by its user: …), a real unsent draft (unsent draft typed by its user: …).

send→queued (busy / typing / blocked)→idle 3 s + guard clear→pointer line typed→read by id

05 · sidebar v2 / v3

A sidebar that shows who needs you

One row per tab across every space, grouped and foldable. From top to bottom: toolbar, detail strip, list, Active, Pinned, Scheduled, fixed rows, status footer. The chrome sits on the theme's surface_dim.

☰Detail strip on top

About the hovered row, else the focused tab: status and time, agent, team role, reminders, browser use, colour tag, context use.

▾Active · Pinned · Scheduled

Active: blocked first, then voice, working, idle-with-subagents, finished, longest first. Pinned: tabs you pin from the menu. Scheduled: tabs with a reminder and the time to the next one. Folded headers keep their count.

◌Suspended runs fold

Three or more suspended tabs in a row become one ◌ N suspended ▸ row. Hover lists them. Off in Settings → Indicators (fold suspended runs).

%Context use

NN% on the row from 75% (yellow), red from 90%. The detail strip shows ctx 78% · 156k/200k at any level.

✎Context menus with sections

Every right-click menu reads the same: titled rules (─ Agent ──), one glyph per item, your own key bindings dim on the right (⌥t, ^b X), toggles as ○/● (☆/★ for Important), and destructive items in red, last behind a rule.

⌕Search and recency filters

Hover the toolbar for ⌕ search and ◷, or press prefix+f (keys.sidebar_search). Typing keeps the tabs whose label, group or agent kind has every term; Esc clears, Enter jumps to the first match. ◷ cycles 15m · 30m · 1h · 6h · 1d of last activity (shift or right click goes back); busy and pinned tabs always pass it. Both AND together; the focused tab, fixed rows and the Active / Pinned / Scheduled blocks stay. A dim ~ N filtered row clears everything. Previous / next tab (keys.previous_tab / keys.next_tab) cycle only the listed tabs while a filter is set. Not saved across restarts.

Your notes page beside every agent

✎Your page, edited in place

One markdown page per agent session: a plan, a checklist, whatever fits. Click to edit; saves on Esc or after 2 s idle. - [ ] tasks tick with a click. Toggle with keys.toggle_info_pane, the menu or the toolbar's ◧; opening never takes your keyboard (click into the pane to type there).

❦Markdown, drawn for a terminal

Headings, bold, italic, links, numbered and nested lists, quotes, code blocks, rules and tables, in the dock's palette. Clicks land on the source text.

◇Agents write it when you ask

Ask directly, or use /plus:notes (a brief page: what is in flight, what waits on you, the plan) or /plus:notify; /plus:notes also opens the pane for you (agents_notes_write reveal=true). Once asked, the agent keeps it current. No running log, no checkpoints.

↻Survives /clear and compaction

The page (its first 3 KB) is put back into the agent's context at start, resume, /clear and compaction.

08 · more

Smaller things that add up

◫Agent wrap & Settings → Agents

herdr agent wrap claude|codex adds the herdr_agents tools and herdr+ instructions. Off by default; Settings → Agents turns it on and shows the exact .zshrc line before it fixes anything. It also switches program status reports and handoff & compact, steps the handoff threshold (60 · 70 · 80 · 90 · off) and the autosuspend time (1h · 4h · 1d · 3d · off); the handoff command and context windows show there read-only.

⏎Launch gate

herdr waits until the new tab's shell is ready before typing a launch, and runs long launch lines from a one-shot script, so nothing gets cut off.

◉Better detection

Codex voice mode shows on the tab. A Claude whose turn ended while background agents run reads idle, not working.

⌁Claude's own status (OSC 7501)

herdr answers Claude Code's status probe and keeps what it reports: working, blocked with the prompt, done, and each background subagent. herdr agent explain shows it next to screen detection, which still decides. Disagreements longer than 2 s go to program-status-disagreements.jsonl. [agents] program_status = false turns it off; Claude stays silent while CLAUDE_CODE_DISABLE_TERMINAL_TITLE is set.

%Context usage

Read from the tail of the agent's own session file after state changes, never per frame. Also in agent.list as context.

⎘Copy session ID

Tab and pane menus copy the Claude session uuid or Codex thread id.

⇆cmd+[ / cmd+] tab history

Back and forward through the tabs you focused, like a browser. Closed tabs are skipped.

⤧Drag & drop and resize fixes

Drops land where the indicator shows. A window drag sends one size every 300 ms instead of ten a second, and the sidebar no longer flashes during it.

◎Built-in browser

herdr runs its own Chromium for agents (herdr-browser MCP): tabs grouped per agent, a glow and cursor while an agent acts, password fields protected, never pulls the window forward.

◌Suspend, activate, restart

Park an agent and bring it back in the same pane with its session. Transcripts are backed up so --resume keeps working. Background shells, monitors and /loops hold a suspend back, like subagents.

◌Autosuspend

[agents.autosuspend] after = "1d" (off by default; Settings → Agents steps 1h · 4h · 1d · 3d · off) parks a Claude agent left idle and seen that long. Never one that is blocked, finished but unseen, on screen, the coordinator, busy in the background or with messages waiting. The detail strip reads suspended (auto); a message to it wakes it and goes in once it is up.

⌂Removed worktree, session back

A pane whose saved directory is gone after a restart starts in a recreated, empty one at the same path, so --resume still finds the session. You get one card; an agent is told through the message queue and asked to tell you first, even when it takes minutes to come up.

⇢Backgrounded Claude sessions

A Claude session you background carries on under a new id outside the pane. Resume, restart and restore follow its continued-in records to the newest session, and its herdr_agents tools still act as its pane (found by session id, the pane's own rights). If herdr cannot find the pane, the error says to claude --resume <id> in it.

↺Recently closed sessions

Closed agent tabs can be reopened with label, colour, group and reminders (herdr tab reopen, Settings → closed).

■Tab colours & groups

Colour tags, foldable groups, drag tabs and groups, move to group by name.

❧AI news desk

A pinned News tab that runs a news edition at fixed times and marks what is new since you last read.

09 · auto handoff & compact

Auto handoff & compact

When a Claude agent's context fills up, herdr has it write a handoff, compacts it, and brings it back on the same work, without you pasting anything.

80% context or manual→transcript snapshot→handoff.md→/compact→resume

◔Two ways to start

Automatically at [agents.handoff] at_percent (80 by default, 0 = off), once per compaction cycle and only while the agent is idle. Or by hand: tab menu “Handoff & compact”, a key, herdr agent handoff <target>.

✎Your handoff skill, or herdr's

Set command to your own skill line with a {path} placeholder, or leave it empty for herdr's short prompt. If the agent never writes the file, herdr writes a mechanical handoff from the notes page, git state and recent prompts.

▤Known place, nothing lost

Each run keeps transcript.jsonl and handoff.md under handoffs/<session>/<time>/, with a latest pointer. The sidebar shows “handoff 12m ago”.

↻Back to work

After /compact the agent's new context names the handoff and transcript, and a short line asks it to continue, or to pause if nothing was in flight.

⛨Safety net

When Claude compacts on its own or you type /compact, herdr still saves the transcript and a handoff first. Messages wait for the run; nothing is typed over you. A /clear or another session in the pane ends the run, and another agent cannot hand the same agent off again within 10 minutes.

10 · engineering notes

How the fork stays healthy

⇄Protocol-compatible

New features ride new API methods and optional pushes. Protocol 25 and endpoint generation 1 hold, so an install is a live handoff: no restart, sessions keep running.

§FORK.md merge contract

Owned files, fields, enum variants, methods, merge rules and a watch-list. The fork-sync tool reads it and refuses a sync that would collide.

✓Audited

Big features go through tri-audits and a cross-model check, then live smoke tests on a throwaway dev server.

↑Synced with upstream

On upstream herdr 0.9.3 (master 2563803d).
