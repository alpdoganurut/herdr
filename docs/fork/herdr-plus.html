01 · coordinator

A coordinator agent, run by herdr itself

One long-running Claude Code session that knows who is doing what, keeps a dashboard, remembers things for you, and acts for you when you ask. It is not a relay: agents talk to each other directly, it sees the log.

◉Native, server-run

The herdr server starts it in a coordinator tab, resumes it, and relaunches it if it goes missing. Turn on with [coordinator] enabled = true.

▤HTML dashboard on 127.0.0.1:7718

Served by herdr. Live data (agents, status, messages, actions) plus the coordinator's own summaries and suggestions. Opens in herdr's browser or yours.

❖Its own memory

memory/ with one fact per file and a MEMORY.md index it reads on every start and wake-up. State lives in files, so it can restart fresh.

⊘Acts only on your word

Write tools refuse unless the turn started from your own typing in its pane (non_user_turn). Wake-ups update the board and suggest; they never act.

02 · agents control herdr

Agents can drive herdr, within clear rules

Every Claude Code or Codex agent can get the herdr_agents MCP tools. One server-side check decides what each agent may do. Every write and every refusal is logged.

›User turns are tracked

herdr knows whether a turn started from your typing or from a script, message or wake-up. Sensitive actions need your turn.

≡Actions log

Every agent write, every refusal, and your own tab and team actions go to actions.jsonl. The dashboard shows it; agents_actions reads it.

≤Loose limits, server-side

200 messages an hour, a 30-in-10-minutes loop guard per pair, 20 spawns an hour, 300 soft edits an hour.

03 · teams

Turn a group into a team

A group of tabs becomes a team with a purpose and roles. Members know each other from their first turn.

◆Make team from a group

Make team… on the group menu, herdr team make <group> --purpose T, or the coordinator. The header shows ◆ <purpose>.

@Roles name the members

Every Claude or Codex started in the group joins. A member is named after its role: fixer, reviewer, reviewer-2. Address one by to="role:lead".

≣Roster in the instructions

The roster, roles and purpose go into the system prompt. Changes reach Claude through a hook on the next prompt, and Codex on its next tool result.

↩Report-back rule

A member that finishes, gets stuck on, or drops work it was given sends one short report: what is done, where the details are, what is next.

04 · agent-to-agent messaging

Messages that never type over you

Sending to a busy agent used to fail or land on top of your half-written prompt. Now the server queues it and types it in at the right moment.

what the receiving agent sees
> herdr+ message m_7f3a from reviewer (teammate, w3:p2): read it with agents_messages id=m_7f3a ● agents_messages(id="m_7f3a") ⎿ from reviewer · "auth review done, 2 issues in session.rs, notes in ## Log"

⇶Server-side queue

Per target, oldest first. Saved with the session, survives restarts. Expires after 2 h, dropped if the target is gone.

‖Typing guard

Nothing is typed while you typed in that pane in the last 10 s, or have an unsent draft in its input box.

›Pointer-line delivery

One short plain line instead of a paste, so Claude does not treat it as your pasted content. The agent reads the full message by id.

⧉Batch delivery

Several queued messages go in together once the target has been idle for 3 s, as one line.

⏱Stuck-message notice

If a message waited 10 min on an agent whose screen has not moved for 10 min, the sender gets one notice with the reason.

!Urgent interrupt, safely

urgent=true: one Esc to a working agent, then the message goes first. Only from your turn or the coordinator; once per pair every 5 min. Never into a dialog, voice mode, or while you type.

↯Claude turn hooks

Claude reports each turn's start and end, so messages are not stuck behind background agents that keep its spinner going.

⇣Wait backlog + inbox

agents_wait_for_message returns what is already queued for you first. agents_messages inbox=true lists it without taking it.

✓Exactly once

A waiting agent claims a message before it is returned, so it is never also typed in, and never returned twice.

◔100 s waits

Waits stop at 100 s, under Claude Code's 120 s mark, and a timeout is a normal result, not a failed tool call.

❯Suggestions are not approvals

agents_read marks a Claude Code or Codex prompt box: a dim suggestion reads (suggestion shown by the agent, not typed by its user: …), a real unsent draft (unsent draft typed by its user: …).

send→queued (busy / typing / blocked)→idle 3 s + guard clear→pointer line typed→read by id

06 · info pane

Notes and history beside every agent

A dock on the right of the pane. Notes are the agent's memory; History is its timeline. Nothing is computed until you open it.

✎Notes, edited in place

Markdown notes per agent session. Click to edit; saves on Esc or after 2 s idle. - [ ] tasks tick with a click. Toggle with keys.toggle_info_pane or the menu.

◇Checkpoints

Decisions, milestones, failures and notes the agent marks, plus your bookmarks. Expand one to see the prompt and reply around it.

◷Auto history

herdr adds its own dim checkpoints: a bookmark per prompt you send, a milestone per commit, a failure when an agent stays blocked 10+ min.

↻Survives /clear and compaction

The last 60 lines of notes and 8 checkpoints are put back into the agent's context at start, resume, /clear and compaction.

▣Agent cards (agents_notify)

Kinds: info, question, done, warning. Accent from your theme: done green, info blue, question and warning red. The team and role sit in the top border. A question rings, done plays the done sound.

✍You decide when

★Reminders and important tabs

Important: reminds you while the agent waits on you. Remind: 5m, 10m, 30m, 1h, 6h or daily, whatever the agent does. Sticky cards optional.

08 · more

Smaller things that add up

◫Agent wrap & Settings → Agents

herdr agent wrap claude|codex adds the herdr_agents tools and herdr+ instructions. Off by default; Settings → Agents turns it on and shows the exact .zshrc line before it fixes anything.

⏎Launch gate

herdr waits until the new tab's shell is ready before typing a launch, and runs long launch lines from a one-shot script, so nothing gets cut off.

◉Better detection

Codex voice mode shows on the tab. A Claude whose turn ended while background agents run reads idle, not working.

%Context usage

Read from the tail of the agent's own session file after state changes, never per frame. Also in agent.list as context.

⎘Copy session ID

Tab and pane menus copy the Claude session uuid or Codex thread id.

⇆cmd+[ / cmd+] tab history

Back and forward through the tabs you focused, like a browser. Closed tabs are skipped.

⤧Drag & drop and resize fixes

Drops land where the indicator shows. A window drag sends one size every 300 ms instead of ten a second, and the sidebar no longer flashes during it.

◎Built-in browser

herdr runs its own Chromium for agents (herdr-browser MCP): tabs grouped per agent, a glow and cursor while an agent acts, password fields protected, never pulls the window forward.

◌Suspend, activate, restart

Park an agent and bring it back in the same pane with its session. Transcripts are backed up so --resume keeps working.

↺Recently closed sessions

Closed agent tabs can be reopened with label, colour, group and reminders (herdr tab reopen, Settings → closed).

■Tab colours & groups

Colour tags, foldable groups, drag tabs and groups, move to group by name.

❧AI news desk

A pinned News tab that runs a news edition at fixed times and marks what is new since you last read.

10 · engineering notes

How the fork stays healthy

⇄Protocol-compatible

New features ride new API methods and optional pushes. Protocol 25 and endpoint generation 1 hold, so an install is a live handoff: no restart, sessions keep running.

§FORK.md merge contract

Owned files, fields, enum variants, methods, merge rules and a watch-list. The fork-sync tool reads it and refuses a sync that would collide.

✓Audited

Big features go through tri-audits and a cross-model check, then live smoke tests on a throwaway dev server.

↑Synced with upstream

On upstream herdr 0.9.3 (master 2563803d).
